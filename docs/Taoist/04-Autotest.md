# Taoist - Autotest and evidence

The scenarios of [03-Test-Scenarios](03-Test-Scenarios.md) run **inside the real game**: ModLib/Taoist need the Il2Cpp game runtime, so they cannot run in a normal test runner (see [Unit tests](#unit-tests)).

## Pieces

| Piece | Location | Role |
|---|---|---|
| Orchestrator | `scripts/game/run-autotest.ps1` | Writes the request, starts the game (`run-game.ps1`), shows progress, collects evidence, writes the report and the OK/NG status |
| In-game runner | `ModMain/Mod/AutoTestEvent.cs` | Loaded **only** while `<game data>\mod\nE7UL2\autotest\request.json` exists. State machine: title scenarios -> load save -> game scenarios -> battle watch -> done |
| Framework | `ModMain/AutoTest/AutoTestContext.cs`, `AutoTestHelper.cs`, `AutoTestScenarios.cs` | Request/result models, `Assert/AssertEqual/AssertBetween/Info/Skip/Snap`, registry that finds every scenario class by reflection |
| Scenarios | `ModMain/AutoTest/Scenarios/<Group>/<Id>_<Feature>.cs` | One class (`IScenarioDefinition`) per scenario id. Groups: Title, Core, Economy, Unit, BattleRule, Progression, UI, Battle |
| Definitions | `3161035078/tests/scenarios.json` | All ids (auto, watch) with description/preconditions/steps/expected; there are no manual scenarios any more (every former `TM-nn` id is covered by an automatic one, see `replaces`) |
| Status | `3161035078/tests/scenario-status.json` | Latest OK/NG of every id (and of every check id), JSON with 2-space indent |
| Viewer | `test-viewer/` (`index.html`, `style.css`, `app.js`) + `scripts/update-test-viewer.ps1` | Results of all autotest and unit test runs, see below |
| Status override | `scripts/game/set-scenario-status.ps1` | Record an OK/NG by hand (e.g. after checking a NG in the game), `-Open` opens the viewer on the Scenario status tab |

## Running

```powershell
# 1. Build + deploy, then the pre-test TP-01 creates a NEW character for the run (S&M trainer on,
#    CrueltyShura) in a free save slot; every scenario runs on it, the restore removes it afterwards
.\scripts\game\run-autotest.ps1 -Deploy

# same on an existing save instead (no TP-01): by name, or the first save of the list
.\scripts\game\run-autotest.ps1 -Deploy -Save "AutoTest"
.\scripts\game\run-autotest.ps1 -Deploy -ExistingSave

# load the save yourself (if automatic loading does not work for your save list)
.\scripts\game\run-autotest.ps1 -ManualLoad

# auto scenarios, then play battles for 15 min: TB-xx run on every battle
.\scripts\game\run-autotest.ps1 -Save "AutoTest" -WatchBattles -WatchMinutes 15

# a subset / only the ids NG or NOT RUN in scenario-status.json / list ids with their latest result /
# rebuild a report without the game. A subset uses the existing save (first of the list) unless a selected
# scenario is marked "newCharacter" in scenarios.json (TB-16, TZ-01) or -NewCharacter is given: then TP-01 runs.
.\scripts\game\run-autotest.ps1 -Scenario TG-04,TG-10
.\scripts\game\run-autotest.ps1 -Failed
.\scripts\game\run-autotest.ps1 -Scenario TS-01 -NewCharacter
.\scripts\game\run-autotest.ps1 -ListScenarios
.\scripts\game\run-autotest.ps1 -ReportFrom logs\autotest\20261115-170000

# keep a run: pinned runs are never deleted by the retention (newest 10 runs) of the test viewer; a full run where
# every scenario passed is pinned automatically (newest 3 auto pins kept)
.\scripts\pin-test-run.ps1 -List
.\scripts\pin-test-run.ps1 -Best -Note "full run before the release"
.\scripts\pin-test-run.ps1 -Run 20261117-074658 -Unpin
.\scripts\pin-test-run.ps1 -Unit -Latest

# record a result by hand
.\scripts\game\set-scenario-status.ps1 -Id TG-45,TG-46 -Result OK
.\scripts\game\set-scenario-status.ps1 -Id TG-46 -Result NG -Note "item not transferred"
.\scripts\game\set-scenario-status.ps1 -List -Only NG
.\scripts\game\set-scenario-status.ps1 -Open     # HTML view of all ids
```

Options: `-Timeout` (s, default 900), `-StepDelayMs` (default 1500), `-KeepGame` (do not close the game), `-GamePath`.
Exit codes: 0 all OK, 1 setup error, 2 runner did not finish (timeout, save not found), 3 at least one NG.

Automatic save loading clicks the title screen "Continue/Into" button and the save whose name or folder equals `-Save` (first save when empty). If it fails, the run ends with `load-timeout`/`save not found` in the runner log: use `-ManualLoad`.

## Where are the results? Evidence

1. **Console**: one line per scenario while it runs (`[OK]`, `[NG]`, `[SKIP]`), then a summary with the NG ids.
2. **Test viewer** `test-viewer/index.html` (open the file in a browser, no server needed). Data: `test-viewer/data/runs.js`, regenerated by `run-autotest.ps1`, `run-unittests.ps1` and `set-scenario-status.ps1` (or `scripts\update-test-viewer.ps1 -Open`).
   * **Autotest** tab: by default *Latest result of every scenario* (first entry of the *Run* list): the last result of each scenario id over all kept runs, each row showing (and linking to) the run it comes from, with that run's screenshots and mod log; any single run from the *Run* list or the history bar (one colored square per run). Summary (OK/NG/SKIP/not run, checks, screenshots, versions, player), filter OK/NG/SKIP and search; a scenario row expands into its **evidence by step** (one card per step: the screen before the scenario and after every step, with the checks of that step under the image) and the **mod log written while the scenario ran** (errors highlighted). The **Logs** card at the bottom shows every log of the run (runner, ModLib/Taoist logs incl. the save-game log, MelonLoader, Unity player) with an errors-only switch and a line filter.
   * Clicking a thumbnail opens the **image viewer**: mouse wheel / `+` `-` zoom (around the cursor), drag to move, double click or `0` = fit, `1` = 100 %, `<-` `->` previous/next screenshot of the scenario, strip of all its screenshots, `Esc` to close.
   * **Unit tests** tab: every unit test run (latest by default), grouped by class, failures expand to message and stack.
   * **Scenario status** tab: the latest OK/NG of every id with its history over the last autotest runs; every id expands to its description, preconditions, steps and expected. The header buttons **Expand all / Collapse all** work on the Autotest, Unit tests and Scenario status tabs (after filters).
   * Deep links: `index.html#tab=auto&run=<run id>&sc=<scenario id>&img=<n>&q=<search>&logs=1`, `#tab=unit`, `#tab=status`.
3. **Run folder** `logs/autotest/<yyyyMMdd-HHmmss>/` (git-ignored) - the raw evidence:

   | File | Content |
   |---|---|
   | `report.json` | Final results read by the viewer (checks with ids, log-error rule applied, screenshots by step) |
   | `results.json` | Raw results written by the game (status, checks, screenshots, error stack, runner log) |
   | `screens/*.png` | Screenshots of the game window `<nnn>_<scenario id>_<step no>-<label>.png`: `00-before` then one after every step. Taken by `run-autotest.ps1` (PrintWindow, works when the window is covered) when the runner asks for one (`<autotest>\snaps\*.req`): `UnityEngine.ScreenCapture` is stripped from the game |
   | `game-run/` | Copy of the `run-game.ps1` session: `timeline.log`, `mod-flQrxq-*.log` (ModLib/Taoist logs, `[AUTOTEST]` lines), `melonloader.log`, `player.log`, `summary.json` |
   | `save-backup/` | Saves and ModLib caches before the run (restored automatically afterwards) |
   | `summary.json` | Counts, exit code, NG ids, number of screenshots |

4. **Status by id** `3161035078/tests/scenario-status.json` (committed): latest OK / NG / SKIP / NOT RUN of every id, the NG check ids, date, tester and evidence link. Automatic ids are updated by every run, manual ids by `set-scenario-status.ps1`.

A scenario is **NG** when one of its checks fails, when a step throws, or when ModLib logs an error (`【Error】`) while it runs (check id `<id>-LOG`), even if its own checks passed.

## VS Code tasks and retention

Tasks (`Terminal > Run Task`, group `test`): **Test: Unit Tests**, **Test: Unit Tests (incl. Known Issues)**, **Test: Autotest** (deploy + all scenarios, asks for the save), **Test: Autotest (selected scenarios)**, **Test: All (Unit + Autotest)** (`scripts/run-all-tests.ps1`, then opens the viewer), **Test: Open Test Viewer**.

Only the newest 10 runs of `logs/autotest`, `logs/unittests` and `logs/game-runs` are kept: `scripts/update-test-viewer.ps1` (called after every run) deletes older run folders (`-Keep N` to change, `-Keep 0` keeps everything).

## Evidence rules (what a screenshot must show)

* Run order: `TT` (title) -> `TP` (pre-test: new character; only for a full run, `-NewCharacter` or a selected scenario with `"newCharacter": true` in scenarios.json) -> `TG` (game) -> `TB-03+` (battles started by code; TB-10..TB-15 = lost battle with each lose option) -> `TX` (time-changing: skip 1 year, currency reform, rebirth) -> `TZ` (ends the character: one-life). The save is restored after the run.
* Before each scenario the runner closes every non-base UI (game announcements, leftovers), so the "before" shot shows the real state.
* Town scenarios first **travel** to a matching town (`TownTestHelper.FindTown` + `TravelTo`) and open the real town UI (`OpenTownUI`, `town.OpenBuild()`); battle scenarios start the battle by code (`JoinMonstWave`, `IntoBattle`), hit/kill units (`PlayerHit`), end it (`EndBattle`) and wait until the map is back (`Wait(...)` steps poll a condition with a timeout).
* Steps that only check data (no UI) show an in-game overlay panel with their checks (`Scenario.Overlay`, default true; set false when the step opens its own UI).
* Viewer: 4 screenshots per row on wide screens; tab **Mod logs** shows the newest logs of `%USERPROFILE%\AppData\LocalLow\guigugame\guigubahuang\mod`; unit test rows expand to the description and the values written by `Check` (`OK what: expected X, actual Y`).

## Adding a scenario

1. Add an entry to `scenarios.json` (`id`, `kind`, `feature`, `title`, `description` (what the feature does and what the test proves, shown in the test viewer), `preconditions`, `steps`, `expected`) and run `python scripts/game/export-scenarios-doc.py`.
2. For auto/watch: add `AutoTest/Scenarios/<Group>/<Id>_<Feature>.cs` and the `<Compile Include>` line in `ModMain.csproj`:

```csharp
public class TG29_MyFeature : IScenarioDefinition
{
    public string Id => "TG-29";
    public Scenario Create()
    {
        return new Scenario { Id = "TG-29", Feature = "MyFeatureEvent", Title = "..." }   // Scope = Title/Game/Battle, Kind, Trigger
            .Step("check", c =>
            {
                c.Assert(MyFeatureEvent.Instance != null, "loaded");
                c.Snap("my-ui");
            })
            .Step("close", c => { ... }, delayMs: 2000);
    }
}
```

Rules: revert what you change on the save, never call the world run / save, prefer `Skip` when a precondition is missing, keep check order stable (check ids are positional).

## Unit tests

Project `tests/UnitTests` (MSTest, .NET Framework 4.7.2) for the code that does not need the running game. Run:

```powershell
.\scripts\run-unittests.ps1                       # builds ModLib + Taoist (Release), then runs the tests
.\scripts\run-unittests.ps1 -NoBuild -Filter "FullyQualifiedName~Taoist"
.\scripts\run-unittests.ps1 -NoBuild -IncludeKnownIssues   # also the tests reproducing open bugs (they fail)
```

Results: console + `logs/unittests/unittests.trx`. The tests reference the mods' build output (`<project>/debug/.../dll`) and resolve the game assemblies from `<game>\MelonLoader\Managed` at runtime (`TestSetup.cs`); pass `-GameFolder` if the game is not in the default Steam folder.

| File | Covers |
|---|---|
| `ModLib/ValueParseHelperTests.cs` | `ValueHelper` (IsBetween, FixValue, Is, NearlyEqual, SafeSumInt), `ParseHelper` (Parse, defaults, ParseJson) |
| `ModLib/ObjectTests.cs` | `EnumObject` lookups, `EnumObjectConverter` round trip, `MultiValue`, `MathLogicOptions`, `EncryptionHelper`, `PngEncodeHelper` chunks, `ModBattleEvent` damage keys/types |
| `Taoist/FormulaTests.cs` | `ExpertEvent.GetExpertNeedExp`, `SMLocalConfigsEvent.Calculate`, `PriceHelper.UpPrice` and ratio tables, `BattleModifyEvent.BlockRatio` |
| `Taoist/ConfigTests.cs` | every ModConf JSON parses, `mod_configs.json` sections/keys match `ModStts`, bank fees, unique CacheIds, `_EventOrderIndex.json` vs events, every `GameTool.LS("key")` exists in LocalText, unique LocalText ids/keys, `scenarios.json` vs scenario classes |
| `KnownIssues.cs` | `[TestCategory("KnownIssue")]` tests reproducing [../Known-Issues.md](../Known-Issues.md) (BUG-07/08/09), excluded by default |

What can / cannot be unit tested:

| Code | Unit-testable? | Why |
|---|---|---|
| Pure helpers (ValueHelper, ParseHelper, EncryptionHelper, PngEncodeHelper, EnumObject, MultiValue...) | Yes | BCL/Json.NET only |
| Taoist formulas mixed with game calls (`g.world`, `CommonTool.Random`, `GameTool.LS`) | After refactoring | Extract the math into pure static methods |
| JSON configs and code/config consistency | Yes | File-level checks |
| Anything using `g.*`, units, UI, `DynInt`, **Il2Cpp enums** (`MartialType`, `MonstType`: "Method in an Enum" TypeLoadException) | No | Needs the running game: covered by the in-game autotest |
